1. Introduction

This project implements watchdog, a process supervisor written in C for Linux using only POSIX system calls. The watchdog starts a set of worker processes with fork() and execv(), detects their termination through SIGCHLD and waitpid(), restarts workers that terminate unexpectedly (at most three times), writes a status report when it receives SIGUSR1, and shuts all workers down in a controlled way on SIGINT or SIGTERM. Every significant event is written to a timestamped log file.

The main design goal was correct and safe signal handling: signal handlers never do real work. They only record that a signal arrived, and all processing happens in the main control loop. The project is split into three modules, one per group member, so that each member's work is visible as a separate part of the code base and of the commit history.

2. Architecture

The program consists of one supervisor process (the watchdog) and three supervised children, all running the test program ./worker in different modes. Signals from the user, the kernel and the interval timer are turned into flags by the signal manager; the main loop reads these flags and calls the process manager or the logger.

3.1 Async-signal-safety

  • Handlers only write flags. Each handler stores into a volatile sig_atomic_t variable and returns. There is no printf, no file I/O, no malloc and no fork in signal context. Logging, reaping, restarting and killing are done by the main loop.
  • Handlers never interrupt each other. Every handler is installed with an sa_mask that blocks all five handled signals while it runs. This also makes the “second shutdown signal” check (read, then write) safe.
  • SA_NOCLDSTOP on SIGCHLD: only real terminations are reported, not stops or continues.
  • SA_RESTART on every handler, as an extra safeguard so that an interrupted system call is restarted instead of failing with EINTR.

3.2 No lost signals

A classic bug in signal-driven programs is the window between checking a flag and going to sleep: if the signal arrives in between, the program sleeps although there is work to do. sm_install() therefore blocks all handled signals with sigprocmask() before installing the handlers and before the first fork(). Signals that arrive while the main loop is working stay pending. They are delivered only inside sigsuspend() (main loop) or pselect() (shutdown wait with a timeout), which unblock the signals and sleep in one atomic step. Because handlers can only run there, the read-and-clear accessors in the main loop cannot race with a handler.

Several SIGCHLD signals may be merged into one by the kernel. The process manager therefore calls waitpid(-1, &status, WNOHANG) in a loop until no more terminated children are found, so no child is left as a zombie.

3.3 Signals and child processes

A child created by fork() inherits the parent's signal mask, and exec() keeps it. Without special care the workers would start with SIGTERM blocked and would never react to the shutdown request. The child therefore calls sm_child_reset() between fork() and execv(); it restores the default dispositions and the original signal mask using only async-signal-safe calls. The child also calls setpgid(0, 0) so that it runs in its own process group: Ctrl+C in the terminal reaches only the watchdog, which then stops the workers itself in a controlled order. The log file is opened with O_CLOEXEC, so workers do not inherit its descriptor.

4. Child Process Management

The watchdog supervises three children, configured in main.c:

ChildCommandPurpose / expected behaviour
alpha./worker alpha foreverruns until stopped; used for the SIGKILL crash test
beta./worker beta exit-ok 8exits with code 0 after 8 s: normal termination, not restarted
gamma./worker gamma crash 4exits with code 1 every 4 s: restarted 3 times, then given up
  • Creation: fork(), then in the child setpgid(0, 0), sm_child_reset() and execv(). If execv() fails the child calls _exit(127), which the parent sees as an unexpected termination. Between fork() and execv() the child uses only async-signal-safe calls (the error message is written with write()). The parent also calls setpgid(pid, pid), so the process group is set no matter which of the two runs first, then records the PID, the start time and the state RUNNING, and logs START.
  • Normal termination: WIFEXITED(status) with exit code 0. The child is marked EXITED, logged as EXIT … normal and is not restarted.
  • Unexpected termination: a non-zero exit code or WIFSIGNALED(status) (for example SIGKILL or SIGABRT). It is logged as CRASH with the exit code, or the signal number and its description (CRASH alpha pid=N signal 9 (Killed)).
  • Bounded restart: after a crash the child is started again and restarts is incremented, as long as restarts < MAX_RESTARTS (3). After the third restart a further crash moves the child to GAVE_UP (GIVE UP gamma after 3 restarts), so the program can never enter an infinite restart loop. If fork() itself fails during a restart (for example EAGAIN), the child is put in the PENDING state and the next periodic check tries again.
  • Matching PIDs safely: a terminated child keeps its last PID for the status report, but only children in state RUNNING are matched against waitpid() results or signalled with kill(). A PID that the system has reused for an unrelated process is therefore never touched.
  • Periodic check: setitimer(ITIMER_REAL) raises SIGALRM every 5 seconds; the main loop then calls pm_check(). It reaps any child whose SIGCHLD was missed, retries PENDING children and logs the number of children in each state.
  • During shutdown no child is restarted, pending starts are cancelled and every exit is logged as STOP.
  • Resources: the child table is a static array, so the module allocates no memory and has nothing to leak. Every system call's return value is checked and failures are logged with strerror(errno).

5. Graceful Shutdown

When SIGINT or SIGTERM arrives, the main loop ends and graceful_shutdown() runs:

  1. Log SHUTDOWN requested by SIGINT|SIGTERM.
  2. Stop launching new processes: pm_begin_shutdown() disables restarts and cancels pending starts, and pm_stop_timer() disarms the periodic timer.
  3. Reap children that terminated just before the request, so that no stale PID is signalled.
  4. Send SIGTERM to every running child with pm_signal_all(SIGTERM).
  5. Wait up to 5 seconds using pselect() with the remaining time as timeout (measured with CLOCK_MONOTONIC). While waiting, terminated children are reaped as SIGCHLD arrives and SIGUSR1 is still answered.
  6. If children are still running after the timeout, log SHUTDOWN timeout after 5s: sending SIGKILL to N child(ren), send SIGKILL and reap them. A second SIGINT/SIGTERM during the wait (for example pressing Ctrl+C twice) skips the rest of the timeout and sends SIGKILL at once.
  7. Log SHUTDOWN complete, then WATCHDOG EXIT, and close the log file.

Every child is reaped with waitpid() before the watchdog exits, so no zombie or orphan worker is left behind. This is verified by the automated tests (scenarios 6, 7 and 8).

6. Logging and Status Reporting

The logger opens watchdog.log with open(O_WRONLY | O_CREAT | O_APPEND | O_CLOEXEC) and writes every line with write() in a loop that handles partial writes and EINTR. Each line starts with a timestamp ([YYYY-MM-DD HH:MM:SS]) and is also mirrored to stderr. The logger is never called from a signal handler.

7. Build and Usage

make                          # builds ./watchdog and ./worker (-Wall -Wextra -pedantic, 0 warnings)
./watchdog                    # run from the project root; prints its PID

kill -USR1 <watchdog-pid>     # status report
kill -KILL <worker-pid>       # simulate a crash of a test worker
kill -TERM <watchdog-pid>     # graceful shutdown (Ctrl+C does the same)

8.1 Ctrl+C

On Ctrl+C the terminal sends SIGINT to its whole foreground process group. This was reproduced by starting the watchdog as a process-group leader and sending SIGINT to the group (kill -INT -- -<pgid>). Every worker runs in its own process group (PGID = PID), so only the watchdog received the signal. It logged SHUTDOWN requested by SIGINT, stopped all three workers with SIGTERM (each exited with code 0) and exited, leaving no worker or zombie behind. The workers' blocked-signal mask was empty (SigBlk: 0 in /proc) and they did not inherit the log file descriptor.

12. Conclusion

The watchdog meets the requirements of the assignment. It starts and supervises three worker processes with fork() and execv(), detects their termination with SIGCHLD and waitpid(), tells normal exits from crashes and restarts crashed workers at most three times. It writes a status report on SIGUSR1, logs every event with a timestamp, and shuts down gracefully on SIGINT and SIGTERM, falling back to SIGKILL after a timeout.

The most important lesson of the project was how to handle asynchronous signals safely. Handlers only set flags. The real work runs in the main loop. Blocking the signals and waiting with sigsuspend()/pselect() closes the race between checking for work and going to sleep. Splitting the program into three modules with small header interfaces let the three members work in parallel and integrate their parts through pull requests.
